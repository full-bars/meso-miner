# v2026.9.22-1052862940-meso

I fixed a memory leak in the provider connection path, made the test suite deterministic, and refreshed the security blocklist.

## What's Changed

### Fixed

- **Message-pool buffer leak on connect failure** ([#126](https://github.com/full-bars/meso-miner/pull/126)): when the provider tries to reach an upstream peer and that connection fails, the pooled packet was released without returning its buffer to the pool. On any node where dials fail often, that pool grows without bound. The failure branch now returns the buffer exactly once, with a regression test.

### Maintenance

- **Deterministic test suite** ([#124](https://github.com/full-bars/meso-miner/pull/124)): the reload and health tests no longer depend on timing or shared state.
- **Security blocklist sync** ([#125](https://github.com/full-bars/meso-miner/pull/125)): refreshed the content-filtering blocklist to the current published ranges.

## Deploy Notes

- Restart the provider to reclaim memory the leak already took. New connections protect themselves the moment the binary runs.
- Use the normal `urnet-tools update` path, then restart.
