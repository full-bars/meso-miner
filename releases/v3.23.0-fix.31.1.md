# v3.23.0-fix.31.1

> [!NOTE]
> v3.23.0-fix.31.1 brings zero-downtime updates to systemd nodes, adds per-destination contract denial backoff and health-aware proxy selection, and starts ordering proxy launches by what each identity actually earns. It also closes a set of control-plane and hardening bugs, including a `urnet-tools` descriptor double close, a `gogc` value that could switch garbage collection off, and a persisted `metrics on` that never survived a restart. Rebuild and redeploy provider nodes, and update `urnet-tools` and `urnet-docker`.

## 1. Overview & Highlights

- **HotSwap on systemd nodes**: `urnet-tools update` migrates a node's unit to `Type=notify` when the binary it installs can signal readiness, so later updates hand over in place instead of restarting. The unit always follows the installed binary, so a downgrade or rollback puts it back to `Type=simple`.
- **Contract denial backoff**: a destination that keeps denying contracts is retried on a growing per-destination schedule instead of every few seconds.
- **Health-aware proxy selection**: dialers are weighted by success rate, latency and error streak, and the parallel probe batch sizes itself from each strategy's recent results.
- **Earnings launch ranking**: proxies with a proven earnings history launch earlier, and a URL-sourced proxy that has earned is treated like a file proxy.
- **Metrics that survive a restart**: `urnet-tools set metrics on` works without `URNETWORK_METRICS`, on loopback, and a persisted `on` is applied at boot.
- **Hardening**: root writes into user-owned directories no longer follow symlinks, and a descriptor double close in `urnet-tools` is fixed.

## 2. HotSwap on systemd

The installer writes `Type=simple` units, and HotSwap needs `Type=notify` to hand the unit's main PID to the new process, so in 31.0 every systemd node declined HotSwap and updated with a restart.

`urnet-tools update` now migrates the unit to `Type=notify` when the binary it is installing sends `READY=1` at startup, which every build since v3.23.0-fix.31.0 does. The update that performs the migration still restarts the provider, because the running process was started without `NOTIFY_SOCKET`. The update after it is the first that can hot swap.

> [!IMPORTANT]
> A `Type=notify` unit paired with a binary that never sends `READY=1` fails every start. That pairing is why the installer keeps `Type=simple` (#546), so the migration never leaves it behind:
>
> - Installing a binary older than v3.23.0-fix.31.0, or one whose version cannot be read, demotes the unit back to `Type=simple` first.
> - A HotSwap rollback that restores such a binary demotes the unit too.
> - A failed migration is not fatal. It prints a note and the update restarts the provider as before.

The unit's temp and backup files are written without following symlinks, a symlinked unit file is refused, and files `urnet-tools` writes into a user's unit directory are handed to that directory's owner.

Every HotSwap decline now says why in plain language, and outcomes are counted in `urnet_hotswap_outcomes_total{reason="..."}` on `/metrics`.

## 3. Contract denial backoff

After repeated contract denials from one destination, retries back off: none after the first denial, then 15s, 30s, 60s, 120s and 240s, capped at 5 minutes. The wait is recomputed before every retry, so it rises as denials arrive and drops back as soon as a contract succeeds or the denial state expires. State lasts for the current backoff plus two minutes, and a frame carrying several contract errors counts as one denial.

## 4. Proxy selection

- **Composite weight**: success ratio, a latency factor against a 500 ms baseline, and a penalty for consecutive errors, floored at the dialer's minimum weight.
- **Serial ordering**: priority, then success rate, then the most recent success. Each dialer's health is snapshotted before sorting.
- **Adaptive parallel batch**: each client strategy tracks its own 10-second window of dial outcomes. When more than 80% succeed the batch halves; otherwise it uses the configured `ParallelBlockSize`, and it never exceeds it.

## 5. Earnings Launch Ranking

The per-proxy earnings history collected since 31.0 now orders launches:

1. **Warmth**: a proxy holding a valid client JWT dials before one that must mint a new identity, because minting is rate-limited.
2. **Trusted provenance**: within a warmth tier, file and internal proxies go first, joined by URL-sourced proxies whose decayed earnings pass 64 MiB.
3. **Earnings**: within a tier and group, the bigger earner dials first.

Among cold proxies, one unproven URL-sourced proxy is interleaved after every five trusted ones, so new addresses still get tried. A node with no history yet orders by warmth and source only and logs `no history yet`. See `LOG_REFERENCE.md`.

## 6. Control Plane & Metrics

- **`urnet-tools history`**: fixed a timestamp wire-format mismatch that made every invocation fail.
- **`urnet-tools set metrics on`**: without `URNETWORK_METRICS`, the listener binds the first free port in `127.0.0.1:9100-9103` and keeps the probed listener open. Set `URNETWORK_METRICS` to serve it on another address.
- **Persisted `metrics on`**: applied at boot. Previously the value was saved but nothing started the listener after a restart.
- **`gogc`**: only `disabled` turns garbage collection off. `off` in any casing restores the default; before, `OFF` passed validation and disabled collection.
- **`ParseByteCount` (#610)**: `set gomemlimit` accepts common suffixes such as `1536M`, `2G`, `512MB` and `1g`.

## 7. Security & Hardening

- **`urnet-tools` descriptor double close**: `writeStateFile` closed its file descriptor directly and again through the `*os.File` wrapping it. The second close could later hit whatever file had reused the number.
- **Root writes into user-owned directories**: HotSwap counters, unit temp files and unit backups are written with `O_NOFOLLOW`, so a planted symlink cannot redirect a root write.
- **Metrics listener on loopback by default**: an automatically chosen metrics port never binds every interface.
- **CFAA blocklist sync (#609)**.

## Upgrade Notes

> [!IMPORTANT]
> **To get the unit migration on the upgrade to 31.1 itself, run `urnet-tools self-update` before `urnet-tools update`.** The migration runs in the `urnet-tools` that performs the update, and `urnet-tools update` refreshes the tool only after it has updated the providers. Run on its own, `update` upgrades a 31.0 node with a restart as before, and the migration happens on the next release. Either way, the update after the migration is the first that can hot swap.

> [!NOTE]
> Nodes still on v3.23.0-fix.30.9 have the version-reporting gap described in the 31.0 notes. Verify the result with `urnet-tools version` rather than the exit status of `urnet-tools update`.
