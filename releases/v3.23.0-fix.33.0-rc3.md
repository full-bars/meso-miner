# v3.23.0-fix.33.0-rc3

> [!NOTE]
> Third pre-release of the v33 line: rc2 plus test-only fixes for the ICMP test isolation and the cancelled-sequence stats test; the runtime is unchanged from rc2. The line adds the receive-window advertisement the platform's modern-provider gate looks for, ICMP echo, the client dial-failure gates, provider-side fragment reassembly, and the network wallet consent commands. Not a stable release: it is invisible to `urnet-tools update`. Try it on one box first.

## Highlights

- **Resizable transfer windows advertised.** Every Ack the receiver sends carries `receive_window_byte_count`, the out-of-order hold capacity it enforces. The platform's capability probe reads this, together with post-quantum end-to-end encryption, to class a provider as modern. Receive memory is unchanged.
- **Network wallet consent.** `provider wallet challenge`, `provider wallet set`, `provider wallet sign` and `provider wallet status` sign and check the canonical network consent that release settlement pays, instead of the sign-in challenge. `provider wallet sign` serves one local page where a browser wallet extension signs it; the seed phrase never leaves the extension. Run it on your own computer, never on a fleet node. See `scripts/wallet-consent/README.md`.
- **ICMP echo, on by default.** A tunnel client can ping through a provider. It goes through the same security policy as UDP and TCP, uses unprivileged sockets, has fixed NAT-wide flow caps, and switches itself off per address family with one log line when the kernel refuses such sockets. `URNETWORK_ICMP=off` turns it off.
- **Client dial-failure gates.** The multi-client uses the provider's dial-failure answers to warn a failing provider, once the strikes span two or more destinations.
- **Fragments reach the NAT.** A provider reassembles fragmented UDP datagrams from tunnel clients before the parse (each client limited to its own share of the cache), applies policy to the whole datagram, and hands the NAT the complete datagram. An unfragmented IPv6 flow behind an extension header keeps its shard.
- **`urnet-tools wallet`**: `status`, `challenge`, `set` and `sign` wrap the provider's wallet commands, refuse the signing forms on a fleet node, and every urnet-tools command now has full help text, with a test that walks the command tree.
- **The credential is renewed when the platform refuses it**, and refusals count toward the revoked-identity safety net.

## Fixed

- The client send path no longer drops ordinary traffic: the SMTP guard's "not applicable" verdict was treated as a refusal. Provider nodes were not affected.
- The dual-stack group no longer stays on the legacy transport for a whole launch when the first IPv6 probe fails, concurrent stack changes are serialized, and the group's memory budget follows the transports the stack uses.
- Dual-stack standby and pinned-down counters no longer stay on after a stack change or a group close.
- The wallet seed file is read through the descriptor that was checked.

## Known limits

- Transfer-layer upstream work (memory bounds, the reliable lane, subprotocols) is not in this line yet.
- The client send path for ICMP stays off.
