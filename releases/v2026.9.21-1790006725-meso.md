# v2026.9.21-1790006725-meso

> [!NOTE]
> This release ships together with the `v2026.9.21-1790006725-meso` release on `full-bars/sn`, carrying the same parity changes on both forks. On 3.23-fix the same work is `v3.23.0-fix.32.2`.

This is mostly a parity and reliability release. The headline is the audit ring: it now survives a hotswap, and `urnet-tools history` tells the story of an update from start to finish.

## What's Changed

### Added

- **Audit ring survives hotswap** ([#118](https://github.com/full-bars/meso-miner/pull/118)): the old process flushes its audit ring at the handover point, before the takeover message, on every path (systemd, Windows, Docker). The new process merges the ring from disk and deduplicates it, so the commands you issued right before an update are not lost.
- **Lifecycle events in the audit trail** ([#118](https://github.com/full-bars/meso-miner/pull/118)): `urnet-tools history` now shows process start (with the version), the hotswap handoff, and control-socket shutdown alongside the usual `set` and `clear` changes. After an update you see `hotswap` on the old process, then `start` with the new version.
- **Sliding severity scale for provider status** ([#118](https://github.com/full-bars/meso-miner/pull/118)): `active` at 90% or more of configured proxies live, `partial` at 70-89%, `degraded` at 50-69%, `critical` below 50% (including zero), with the exact percentage shown and clamped at 100.
- **Bandwidth and heartbeat reporters ported** ([#103](https://github.com/full-bars/meso-miner/pull/103)): the hub-lane reporters now ship on this lane, and the legacy PowerShell scripts are retired.
- **HotSwap design proposal** ([#111](https://github.com/full-bars/meso-miner/pull/111)): `docs/design/hotswap-make-before-break.md` plans a per-client handover that keeps every client connected. Proposal only, no code.

### Fixed

- **HotSwap reachable on installer-created units** ([#109](https://github.com/full-bars/meso-miner/pull/109)): a unit with no `Type=` line now migrates to `Type=notify`, stale processes are declined up front, and `urnet-tools` is put on PATH by the installer and by `update`.
- **Proxy credential rotation on re-paste** ([#107](https://github.com/full-bars/meso-miner/pull/107)): pasting an address with different credentials rotates the running proxy instead of silently keeping the old ones; pool-leak call sites are named and test suites deflaked.
- **Container-discovery ghost hardening, round 2** ([#106](https://github.com/full-bars/meso-miner/pull/106)): containerized providers no longer appear as host providers, and the state paths are read and written through descriptor-pinned handles.
- **Interactive delegated subcommands wire stdin** ([#105](https://github.com/full-bars/meso-miner/pull/105)): `proxy remove-dead`, `remove`, and `trim` now read your answer instead of timing out on piped runs.
- **Docs fixed and CI retargeted** ([#102](https://github.com/full-bars/meso-miner/pull/102)): stale links updated and the CI workflows point at this repository's own targets.

### Maintenance

- **Security blocklist syncs** ([#101](https://github.com/full-bars/meso-miner/pull/101), [#104](https://github.com/full-bars/meso-miner/pull/104), [#108](https://github.com/full-bars/meso-miner/pull/108)): refreshed the content filtering blocklist three times.
- **Parity completion** ([#94](https://github.com/full-bars/meso-miner/pull/94), [#112](https://github.com/full-bars/meso-miner/pull/112)): repository parity with the 3.23-fix release state, and release-prep groundwork for this release.

### CI

- **Ship-release hands off to the tag pipeline** ([#99](https://github.com/full-bars/meso-miner/pull/99), [#100](https://github.com/full-bars/meso-miner/pull/100)): the one-click ship release dispatches `release.yml` explicitly after the tag push, so the tag-triggered pipeline fires reliably.

## Deploy Notes

1. **No unit changes.** Provider runtime only; existing installs pick this up on the next `urnet-tools update -f`.
2. **`urnet-tools history` shows more.** Lifecycle entries are new; paging and the 1000-entry ring are unchanged.
