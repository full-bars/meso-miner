# Next release

Previous release: [v2026.11.15-1099303040-meso](https://github.com/full-bars/meso-miner/releases/tag/v2026.11.15-1099303040-meso).

I prepared this release to add proxy UDP relay coverage checks, extender UDP carrier controls, gossip observability, and a redesigned status summary. The update also includes the consolidated full-screen dashboard in container images.

Update and restart the provider to apply binary changes. Successfully changing an extender carrier setting restarts an active extender role automatically.

Legend: **[redeploy]** needs the new provider, tool or container image. **[installer]** needs the updated installer or script. **[no redeploy]** covers documentation, CI and tests.

## Upgrade notes

**Providers on a `v2026.11.1-*-meso` release: update to `v2026.11.15` or later.** Those builds drop client UDP (DNS, STUN, QUIC) through proxied identities. Only TCP works. The fix shipped in `v2026.11.6-1091259400-meso`.

Why it matters: the platform checks UDP (HTTP/3) on each connection. A connection that fails the check does not qualify for the quality bucket. The network sends less traffic to that node than to an otherwise equal node that passes, and it promotes quality bucket nodes more. So UDP support is a direct financial incentive.

The same rule applies to your proxies. Choose proxies that relay UDP. A proxy with no UDP relay shows as `no UDP` in `top` and `status`. See the Proxy Management guide.

## Quick start

Already running a provider? Update it in place:

```sh
urnet-tools update
```

Install on Linux:

```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/meso-miner/refs/heads/main/scripts/Provider_Install_Linux.sh | sh
```

Install on macOS:

```sh
curl -fSsL https://raw.githubusercontent.com/full-bars/meso-miner/refs/heads/main/scripts/Provider_Install_Mac.sh | sh -s -- install
```

Install on Windows in PowerShell:

```powershell
irm https://raw.githubusercontent.com/full-bars/meso-miner/refs/heads/main/scripts/Provider_Install_Win32.ps1 -OutFile "$env:TEMP\install-win.ps1"
powershell -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\install-win.ps1"
```

Install on FreeBSD:

```sh
fetch -qo urnet-install.sh https://raw.githubusercontent.com/full-bars/meso-miner/refs/heads/main/scripts/Provider_Install_FreeBSD.sh
sudo sh urnet-install.sh install
```

Install on OpenBSD:

```sh
ftp -o urnet-install.sh https://raw.githubusercontent.com/full-bars/meso-miner/main/scripts/Provider_Install_OpenBSD.sh
doas env SERVICE_USER_OVERRIDE=urnet sh urnet-install.sh install
```

For Docker, pull `ghcr.io/full-bars/meso-miner:latest`.

## Operator actions

- **Extender carrier settings. [redeploy]** Operators can control UDP carriers independently with `urnet-tools set extender-udp443 on|off`, `urnet-tools set extender-udp4053 on|off` and `urnet-tools set extender-udp53 on|off`. Successfully changing a setting restarts the active extender role automatically and persists across reboots. A failed write leaves a running role untouched.
- **Extender discovery default. [redeploy]** Extender discovery defaults to on when the extender role runs. Explicit saved settings for `off` and `feed-only` remain in effect.
- **Scripted health checks. [redeploy]** `urnet-tools status --brief` exits with code 0 for healthy, 1 for warning, 2 for broken and 3 for unreachable. Output is empty when healthy. `urnet-tools status --json` keeps printing the raw snapshot. Automation expecting a fixed format can use `urnet-tools status --json-summary`.
- **Head tier and proxy slots:** A provider that sends the proxy header counts at no head tier unit. Bind direct devices only, and keep a direct slot on the host that you bind.

## What changed

### Proxies and UDP

- **Proxy UDP coverage checks. [redeploy]** The provider sweeps online proxies in the background to verify UDP relay capability. Status and metrics report coverage counts. Proxies are never rejected or graded down for lacking UDP, and only client UDP and QUIC flows are refused through a proxy proven not to relay. A proxy whose UDP check runs over 20 seconds counts as unknown and is allowed. Background sweeps can be paused with `urnet-tools set udp-probe off`.
- **Proxy isolation for DoH and extender carriers. [redeploy]** A provider that runs through a configured proxy no longer resolves platform names over DoH from the host address and does not open host packet sockets for proxied extender carriers.
- **Probe state persistence. [redeploy]** The probe state file is written in the background at most every 2 seconds. The provider restores previous results across restarts.
- **Proxy password parsing. [redeploy]** The `proxy add` parser accepts passwords that contain an `@` sign.
- **Proxied providers keep ICMP and peer connections off the host. [redeploy]** A provider that runs through a proxy opens no host ICMP echo socket and makes no peer-to-peer connections. Its platform connections carry the header `X-UR-Egress-Proxy: 1`. The platform counts a provider that sends the header at no head tier, capture-the-flag or extender unit.
- **The UDP row says `no UDP`. [redeploy]** `top`, `status` and the status snapshot show a proxy without a UDP relay as `no UDP` (`no-udp` in narrow views). Logs and metrics keep the state name `no-relay`.

### Extender and gossip

- **Extender UDP carriers and carrier rollback. [redeploy]** Extender status and the `urnet_extender_dns53_state` metric show whether UDP port 53 is bound or why it failed. A failed carrier setting write restores previous carrier settings and no longer restarts a healthy extender role. A failed live restart is reported to the caller instead of success. The port 53 sysctl threshold exists in the setup code but extender setup does not select it yet.
- **Gossip node hardening and discovery defaults. [redeploy]** The gossip node bounds inbound streams per connection and node resources, refusing extra streams without harming existing peers. Peer dials are restricted to the selected dialer and addresses. Extender role and discovery default to on, so this hardening protects default installs.
- **Gossip observability. [redeploy]** Gossip diagnostics report dial attempts, dial failures, health state transitions and bounded anomaly dumps. The `urnet-tools extender events` command displays recent mesh, dial, reject and cap events. Cap pressure does not hide worse gossip health states.
- **A refused yamux memory reservation resets one stream. [redeploy]** When the gossip node's memory budget is full, the affected stream is reset and the connection and its other streams stay up. The release carries a patched copy of go-yamux (`third_party/go-yamux`, MPL-2.0, see `THIRD_PARTY_LICENSES.md`).

### Status and dashboard

- **Status summary redesign. [redeploy]** Default `urnet-tools status` output presents a one-screen health overview. It shows update availability, proxy pools, UDP coverage, extender state and system resource usage. The status update cache is read safely without following symbolic links. Status honors `--pid` to inspect a specific process.
- **Consolidated top dashboard and container support. [redeploy]** `urnet-tools top` renders proxy health as heatmap dots with a configurable fading glow track. The proxy heatmap spreads small pools over the whole panel. Top graphs follow the refresh speed: `+` and `-` change the graphs together with the metrics. The dashboard includes a UDP coverage row, interactive mouse panels and a decimal unit toggle. Docker images include the dashboard binary. `urnet-docker top` checks that the binary exists before launching.
- **Top copy failure handling and ownership handoff. [redeploy]** Running `top --copy` fails the command when the copy cannot be saved to disk. When elevated, directory ownership is handed to the right user without following symbolic links.
- **Linux interface counters. [redeploy]** The tool reads Linux network interface byte counters from `/proc/net/dev`. Counters that reset between snapshots are handled cleanly.
- **Proxy heatmap popup. [redeploy]** Hover or click a dot in the `top` proxy heatmap to see that proxy's address (host and port only), state, UDP check result, clients, bytes in the interval and age. The direct connection is counted and shown apart from the proxies. A cell that holds two proxies shows each as one half of the cell, and the popup lists both.
- **`top` redraws less and scales its graphs to what is on screen. [redeploy]** The dashboard redraws at most 20 times a second. It used to redraw on every poll result and mouse move, over 100 times a second at a fast refresh. The graph axes follow the visible columns, so one old burst no longer makes live traffic draw one pixel high. Dropped, connecting and dead proxies have their own colors (orange, violet and bold red), and the throughput shades stay in green to aqua. The fade menu item is named `Dot fade time`.

### Security and maintenance

- **Pinned IP family route hold and cause logging. [redeploy]** This is new dial behavior for pinned transports. A pinned IP family with no route is backed off for 5 minutes doubling to 1 hour. A network change or a connection ends the hold. Authentication and contract error lines name the failed causes.
- **Messaging network prefix list refreshed. [redeploy]** The messaging network prefix list is refreshed from registry route objects.
- **Atomic backend failure snapshots. [redeploy]** Backend failure counts and timestamps are published together in one atomic record to prevent mismatched reads.
- **CFAA blocklist sync. [no redeploy]** The CFAA sync commits generated tables straight to main after running format and decoder tests.
- **Unused client window removed. [no redeploy]** The unused FP2 client window and its exported Go API types were removed. Shipped binaries did not use them.
- **Docker images and release archives include the license texts. [installer]** Archives carry a `LICENSES/` directory and images carry `/usr/share/doc/urnetwork/LICENSES/`, including the license of the vendored yamux copy.
- **The README lists Linux, macOS and Windows before the BSDs. [no redeploy]**

## Known limits

- The port 53 sysctl threshold exists in the setup code but `extender setup` does not select it yet. Binding port 53 as a non-root user requires manual configuration.
- An UNVERIFIED part of the IPv6 hold is timer and standby behavior.
- UDP relay verification requires reachability to network endpoints and does not test IPv6 proxy destinations.
